One pinned agent. A competition on how it is instructed.

SN74 Gittensor · Hermes agent · pinned model, sampling and sandbox

A strategy is prose — a SOUL.md and optional skills — and nothing else. The validator runs the same agent and model under every strategy, in a sealed sandbox, on instances whose grading criteria were committed before submissions opened. A strategy is paid for beating the strategy-less baseline on the same instances. The winner becomes the incumbent; every verified trajectory becomes training data.

Compete

  1. Write submissions/<hotkey>/SOUL.md, plus skills/<name>/SKILL.md if you want them.
  2. Run python -m sh.cli.lint submissions/<hotkey> — the same check CI runs, and your bundle_sha256.
  3. Open a pull request against sh/v2-pipeline. The next round seals every open strategy PR by head SHA.
  4. Your scorecard is posted on the PR at close. The crowned PR is merged; the others are closed — resubmit for the next round.

Check

Each round publishes its tasks and seal when it opens, and close.json, reveal.json (every withheld half and salt) and scorecards when it closes. HMAC(salt, withheld) must equal the commitment published at open, and the scores recompute from the graded episodes — nothing here needs to be trusted.
